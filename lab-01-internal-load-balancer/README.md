# Lab 01 — Internal Load Balancer

## Task
**Perfectly balanced, as all things should be**

Complete the Microsoft Quickstart to deploy and test an internal load balancer using the Azure Portal.

## Reference
https://learn.microsoft.com/en-us/azure/load-balancer/quickstart-load-balancer-standard-internal-portal

## Architecture

```
VNet: lb-vnet (10.0.0.0/16) — Germany West Central
│
├── AzureBastionSubnet (10.0.1.0/26)
│   └── lb-vnet-Bastion         ← secure browser-based VM access
│
├── default subnet (10.0.0.0/24)
│
└── backend-subnet (10.0.2.0/24)  ← NAT Gateway attached
    ├── load-balancer             ← Internal Standard LB (frontend: 10.0.2.4)
    │   ├── lb-backend-pool       ← lb-HTTP-rule on port 80
    │   └── lb-health-probe       ← TCP port 80, 5s interval
    ├── lb-VM1  (Zone 1)          ← IIS installed, in backend pool
    ├── lb-VM2  (Zone 3)          ← IIS installed, in backend pool
    └── lb-TestVM                 ← used to test load balancer via browser
```

## Key Configuration Notes

- **backend-subnet uses 10.0.2.0/24** (not 10.0.0.0/24 from the guide) — avoids overlap with AzureBastionSubnet which auto-claimed 10.0.0.0/24
- **lb-VM2 is in Zone 3** (guide says Zone 2, but Germany West Central availability varies)
- **Load balancer frontend IP**: 10.0.2.4 (dynamically assigned in backend-subnet)
- **VM size**: Standard_D2s_v6 (auto-selected)
- All VMs use **Windows Server 2022 Datacenter Azure Edition**
- All resources in resource group **NetworkWatcherRG** (Germany West Central)

## IIS Setup (run on lb-VM1 and lb-VM2 via Bastion)

```powershell
Install-WindowsFeature -name Web-Server -IncludeManagementTools
Remove-Item C:\inetpub\wwwroot\iisstart.htm
Add-Content -Path "C:\inetpub\wwwroot\iisstart.htm" -Value $("Hello World from " + $env:computername)
```

## Test Result

Accessed `http://10.0.2.4` from lb-TestVM browser:
- Shows `Hello World from lb-VM1` or `Hello World from lb-VM2`
- After stopping one VM, traffic automatically reroutes to the remaining VM ✅

## Redeploy from Template

> ⚠️ Passwords are not stored in the template (Azure strips them on export).
> You must supply adminPassword when redeploying.

1. In Azure Portal, search **Deploy a custom template**
2. Click **Build your own template in the editor**
3. Upload `template.json` → Save
4. Fill in required parameter: `adminPassword`
5. Select subscription and resource group → **Review + create** → **Create**

Or using Azure CLI:
```bash
az deployment group create \
  --resource-group NetworkWatcherRG \
  --template-file template.json \
  --parameters parameters.json
```

> Copy `parameters.example.json` → `parameters.json`, fill in your password, and **never commit parameters.json** (it's in .gitignore).
